To make your life even easier, Gradio integrates directly with Hugging Face Hub and Hugging Face Spaces.
You can load demos from the Hub and Spaces with only *one line of code*.

### Loading models from the Hugging Face Hub[[loading-models-from-the-hugging-face-hub]]
To start with, choose one of the thousands of models Hugging Face offers through the Hub, as described in [Chapter 4](/course/chapter4/2).

Using the special `Interface.load()` method, you pass `"model/"` (or, equivalently, `"huggingface/"`) 
followed by the model name. 
For example, here is the code to build a demo for [GPT-J](https://huggingface.co/EleutherAI/gpt-j-6B), a large language model, add a couple of example inputs:

```py
import gradio as gr

title = "GPT-J-6B"
description = "Gradio Demo for GPT-J 6B, a transformer model trained using Ben Wang's Mesh Transformer JAX. 'GPT-J' refers to the class of model, while '6B' represents the number of trainable parameters. To use it, simply add your text, or click one of the examples to load them. Read more at the links below."
article = "<p style='text-align: center'><a href='https://github.com/kingoflolz/mesh-transformer-jax' target='_blank'>GPT-J-6B: A 6 Billion Parameter Autoregressive Language Model</a></p>"

gr.Interface.load(
    "huggingface/EleutherAI/gpt-j-6B",
    inputs=gr.Textbox(lines=5, label="Input Text"),
    title=title,
    description=description,
    article=article,
).launch()
```

instead of loading the model in memory. This is ideal for huge models like GPT-J or T0pp which

### Loading from Hugging Face Spaces[[loading-from-hugging-face-spaces]]
To load any Space from the Hugging Face Hub and recreate it locally, you can pass `spaces/` to the `Interface`, followed by the name of the Space.

Remember the demo from section 1 that removes the background of an image? Let's load it from Hugging Face Spaces:

```py
gr.Interface.load("spaces/abidlabs/remove-bg").launch()
```

One of the cool things about loading demos from the Hub or Spaces is that you customize them 
by overriding any of the 
parameters. Here, we add a title and get it to work with a webcam instead:

```py
gr.Interface.load(
    "spaces/abidlabs/remove-bg", inputs="webcam", title="Remove your webcam background!"
).launch()
```

### Applied Lab: Hub integrations worked decision example[[applied-lab-hub-integrations]]

Deciding between loading via the Hugging Face Inference API (`huggingface/<model>`) and loading an interactive Space application (`spaces/<space>`) depends on host resource constraints, target artifact type, and required UI parameter customizations.

For a concrete three-scenario worked example featuring a deterministic offline service adapter, decision table, and automated checker, see [`chapters/en/chapter9/applied-labs/r16-t025`](applied-labs/r16-t025/README.md).

> [!NOTE]
> **Simulation / Pedagogical Scope:** This lab is a minimal Python standard library simulation illustrating the decision logic and routing prefixes for `Interface.load()`. It operates completely offline via a deterministic local adapter without requiring external network connectivity, Hugging Face API tokens, GPU hardware, or model downloads.

- **Prerequisite Tools:** Python 3 standard library (`unittest`).
- **Fixture Scenarios:**
  - **Normal**: High-RAM model (`EleutherAI/gpt-j-6B`) on 4GB host $\rightarrow$ `LOAD_HUB_MODEL` (`huggingface/EleutherAI/gpt-j-6B`).
  - **Boundary**: Full Space demo (`abidlabs/remove-bg`) with webcam override $\rightarrow$ `LOAD_SPACES_APP` (`spaces/abidlabs/remove-bg`).
  - **Missing Information**: Unspecified artifact type $\rightarrow$ `REJECT_INSUFFICIENT_INFORMATION`.

**Invocation:**
```bash
python3 chapters/en/chapter9/applied-labs/r16-t025/example.py
```
